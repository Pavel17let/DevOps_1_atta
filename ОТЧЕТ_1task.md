# Отчет о выполнении лабораторной работы
## 1. ВВЕДЕНИЕ

### 1.1 Цель работы
Целью данной лабораторной работы является разработка и внедрение полностью функциональной микросервисной платформы интернет-магазина на основе контейнеризации Docker и оркестрации через Docker Compose. Работа направлена на создание воспроизводимого и масштабируемого стенда, который позволяет развернуть весь комплекс сервисов одной командой.

### 1.2 Задачи работы
1. **Докеризация прикладных сервисов** — создание собственных Dockerfile для каждого микросервиса
2. **Оркестрация через Docker Compose** — поднятие всего стека через `docker-compose.yml`
3. **Настройка межсервисной сети** — обеспечение взаимодействия между контейнерами и правильное конфигурирование переменных окружения
4. **Настройка API Gateway** — реализация единой точки входа через nginx-gateway
5. **Проверка функциональности** — тестирование пользовательских сценариев: регистрация, логин, просмотр товаров, оформление заказа, асинхронная обработка

### 1.3 Обоснование выбора архитектуры
В современной разработке микросервисная архитектура является стандартом для крупных систем. Использование различных технологических стеков (Go, Java, Python, React, Nginx) демонстрирует полиглотную архитектуру, что требует особого внимания к интеграции и коммуникации между компонентами. Docker и Docker Compose обеспечивают:
- **Изоляцию окружения** — каждый сервис работает в своём контейнере
- **Воспроизводимость** — одинаковая среда на разных машинах
- **Масштабируемость** — возможность добавления новых экземпляров сервисов
- **Быстрое развёртывание** — полный стек поднимается одной командой

### 2.2 Микросервисы и их компоненты

#### 2.2.1 Auth Service (Go)
**Назначение:** Управление аутентификацией и сессиями пользователей

**Технологический стек:**
- Язык: Go
- Хранилище пользователей: etcd
- Кэш сессий: Redis
- Порт: 8081

**Ключевые компоненты:**

**Файл: auth-service-go/cmd/auth-service/main.go**
- Точка входа приложения
- Инициализация конфигурации
- Запуск HTTP-сервера на порту 8081

**Файл: auth-service-go/internal/config/config.go**
- Загрузка конфигурации из YAML
- Определение параметров подключения к etcd и Redis

**Файл: auth-service-go/internal/app/app.go**
- Основная логика приложения
- Обработка регистрации и логина пользователей
- Управление сессиями в Redis

**Файл: auth-service-go/internal/server/server.go**
- HTTP-сервер с маршрутами
- Обработчики `/login`, `/register`, `/logout`

**Dockerfile: auth-service-go/Dockerfile**
```dockerfile
FROM golang:1.21 AS builder
WORKDIR /app
COPY . .
RUN go build -o auth-service ./cmd/auth-service

FROM alpine:latest
RUN apk --no-cache add ca-certificates
COPY --from=builder /app/auth-service /app/auth-service
COPY config.yml /app/config.yml
EXPOSE 8081
CMD ["./auth-service"]
```

#### 2.2.2 Backend Service (Java/Spring Boot)
**Назначение:** Основной API магазина (товары, заказы, администрирование)

**Технологический стек:**
- Язык: Java 17+
- Фреймворк: Spring Boot 3.x
- БД: PostgreSQL
- Кэш: Redis
- Очередь: RabbitMQ
- Хранилище файлов: MinIO

**Ключевые компоненты:**

**Контроллеры (backend-java/src/main/java/com/shop/backend/controller/):**
- `ProductController` — управление товарами (GET, POST, PUT, DELETE)
- `OrderController` — создание и управление заказами
- `AdminController` — административные функции
- `HealthController` — проверка здоровья сервиса

**Сервисы (backend-java/src/main/java/com/shop/backend/service/):**
- `ProductService` — бизнес-логика товаров
- `OrderService` — обработка заказов, взаимодействие с RabbitMQ
- `SessionService` — валидация сессии пользователя
- `MediaService` — работа с MinIO для хранения изображений

**Модели данных (backend-java/src/main/java/com/shop/backend/model/):**
- `Product` — сущность товара
- `OrderEntity` — сущность заказа

**Конфигурация (backend-java/src/main/java/com/shop/backend/config/):**
- `DatabaseBootstrap` — инициализация БД при запуске
- `CorsConfig` — CORS политика для взаимодействия с фронтенд
- `RabbitConfig` — конфигурация очередей RabbitMQ
- `MinioConfig` — конфигурация S3-совместимого хранилища

**Dockerfile: backend-java/Dockerfile**
```dockerfile
FROM maven:3.9-openjdk-17 as builder
WORKDIR /app
COPY pom.xml .
RUN mvn dependency:resolve
COPY . .
RUN mvn clean package -DskipTests

FROM openjdk:17-jdk-slim
WORKDIR /app
COPY --from=builder /app/target/backend-*.jar app.jar
EXPOSE 8080
CMD ["java", "-jar", "app.jar"]
```

#### 2.2.5 NGINX Gateway
**Назначение:** Единая точка входа в систему

**Маршрутизация:**
```nginx
location /api/auth/  → auth-service:8081/
location /api/       → backend-service:8080
location /media/     → minio:9000
location /           → frontend:80
```

**Ключевые особенности:**
- Docker DNS resolver (`127.0.0.11`) для адресации контейнеров
- Проксирование заголовков сессии (X-Session-Token)
- CORS-совместимость

### 2.3 Инфраструктурные сервисы

#### PostgreSQL
- **Роль:** Основная база данных для товаров и заказов
- **Версия:** 15+
- **Инициализация:** sql-скрипт из `infra/postgres-init/01-init.sql`
- **Порт:** 5432

#### Redis
- **Роль:** Кэш сессий и данных
- **Версия:** 7+
- **Порт:** 6379

#### RabbitMQ
- **Роль:** Брокер сообщений для асинхронной обработки заказов
- **Версия:** 3.12+
- **Консоль управления:** http://localhost:15672
- **Порты:** 5672 (AMQP), 15672 (Management UI)

#### etcd
- **Роль:** Распределённое хранилище конфигурации и пользователей auth-service
- **Версия:** 3.5+
- **Порт:** 2379

#### MinIO
- **Роль:** S3-совместимое объектное хранилище для изображений товаров
- **Версия:** latest
- **Консоль:** http://localhost:9001
- **Порты:** 9000 (API), 9001 (Console)
- **Инициализация:** скрипт `infra/minio-init/init.sh`

### 2.4 Docker Compose конфигурация

**Файл: compose.yml**

Основные параметры:

```yaml
services:
  gateway:          # Nginx с маршрутизацией (порт 3000)
  frontend:         # React приложение
  auth-service:     # Go сервис аутентификации
  backend-service:  # Java сервис API
  order-worker:     # Python воркер для обработки заказов
  postgres:         # База данных
  redis:            # Кэш
  rabbitmq:         # Очередь сообщений
  etcd:             # Хранилище конфигурации
  minio:            # Объектное хранилище
  minio-init:       # Инициализация MinIO (создание бакетов)
```

**Ключевые особенности конфигурации:**

1. **Зависимости сервисов** — использование `depends_on` для обеспечения корректного порядка запуска
2. **Сетевое взаимодействие** — единая сеть `microshop` для всех контейнеров
3. **Переменные окружения** — передача конфигурации через env переменные
4. **Health checks** — проверка здоровья инфраструктурных сервисов
5. **Тома для данных** — персистентность БД и очередей

### 2.6 Процесс разработки и тестирования

#### Этап 1: Подготовка Dockerfile для каждого сервиса
Для каждого микросервиса был создан собственный Dockerfile с использованием мультистадийной сборки:
- **Сборочный этап** (Builder stage) — компиляция кода
- **Финальный этап** (Runtime stage) — минимальный образ с готовым приложением

**Преимущества:**
- Размер финального образа значительно меньше
- Исключение инструментов разработки из production образа
- Улучшенная безопасность

#### Этап 2: Конфигурирование Docker Compose
Разработана комплексная конфигурация `compose.yml`:
- Определение всех сервисов с указанием контекста сборки
- Настройка сетевого взаимодействия
- Определение переменных окружения для каждого сервиса
- Установка зависимостей между сервисами

#### Этап 3: Настройка Nginx Gateway
Реализована единая точка входа с правильной маршрутизацией:
- Проксирование запросов к различным backend-сервисам
- Правильная передача заголовков и контекста запроса
- Использование Docker DNS resolver для динамического разрешения имён контейнеров

#### Этап 4: Инициализация инфраструктуры
Настроены скрипты инициализации для:
- PostgreSQL — создание таблиц и начальных данных (`01-init.sql`)
- MinIO — создание бакетов и загрузка тестовых изображений (`init.sh`)

#### Этап 5: Тестирование функциональности

**Проверка здоровья сервисов:**
```bash
docker compose ps
```
Команда показывает статус всех контейнеров.

**Проверка связности:**

**Сценарии тестирования:**

   ```

   ```

   {

   ```

   ```

   - Backend публикует событие в RabbitMQ
   - Order Worker потребляет и обрабатывает
   - Статус заказа обновляется в БД
